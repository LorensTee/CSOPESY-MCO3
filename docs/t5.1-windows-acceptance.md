## 1. Method and honest scope

The shell that produced this record has no interactive tty, so the harness spawned the built `csopesy.exe` with
`CreateProcess(..., CREATE_NEW_CONSOLE, ...)`, attached to the child's **real Win32 console**
(`FreeConsole` → `AttachConsole(pid)` with a retry, then `CONOUT$`/`CONIN$`), injected keystrokes with
`WriteConsoleInputW`, read the screen back with `ReadConsoleOutputCharacterW`, and resized with
`SetConsoleScreenBufferSize` / `SetConsoleWindowInfo`. That exercises genuine console behaviour
(`GetConsoleMode`/`_kbhit`/`_getch`, `SetConsoleMode`, live size, VT output), not a pipe or a mock.

Two consequences are stated rather than glossed, exactly as the macOS T5.2 record does:

1. The measurements below are **screen-buffer observations**, not a human's eyeball impression. "Looks fluid /
   no visible tearing to the eye" remains pending a person at the CLion terminal (**T3.4**).
2. The harness lives in a temp directory and is **not committed**; the technique is described here so the run
   is reproducible. No repository file other than this record was changed by T5.1.

**A4 non-ASCII.** The rejection path named by §3.7 rule 7 / D15 is implemented (`interpreter.cpp` →
`set_text: only printable ASCII characters are supported.`) and is covered by
`test_interpreter.cpp::set_text_non_ascii_is_rejected_and_unchanged`. It is **unreachable from the keyboard by
design** — the line editor appends printable ASCII only (`line_editor.cpp`), so typing `set_text café` yields
`"caf"`. The line **is** produced on the raw-stdin path §3.7 names, verified directly:

```text
$ printf 'set_text caf\xc3\xa9\nset_text \xe6\x97\xa5\xe6\x9c\xac\nexit\n' | csopesy.exe --no-tty
Command> set_text: only printable ASCII characters are supported.
Command> set_text: only printable ASCII characters are supported.
Command> Exiting CSOPESY. Goodbye!
```

This is the same acceptance/spec inconsistency W4 recorded for macOS: §6.2 case A4 lists non-ASCII as an
interactive input and expects the rejection line, while §3.7's rationale says typing cannot produce an invalid
argument. **No code or contract was changed**; the finding belongs to the plan/A4 wording (W2) and, if it is to
become reachable interactively, to the backends (W1/W3).

**`exit` goodbye count (W2's watch item).** In raw mode the `exit` response (§3.7) is rendered as the message
row, and §3.10's post-join plain line is written after `join()`. On this run the final screen buffer shows
`Exiting CSOPESY. Goodbye!` **once** (the message row); the post-join line is written with the cursor at the
frame's end and the console closes immediately, so it is not separately visible. The `--no-tty` plain-line path
prints it exactly once. No duplication is observable; recorded rather than assumed.
