## 1. What landed

`Win32Terminal` implements the full frozen `Terminal` contract and the two `shutdown.hpp` free functions:

| Member | Windows mechanism |
| --- | --- |
| `enterRawMode()` | saves both console modes; sets VT output + `DISABLE_NEWLINE_AUTO_RETURN`; clears `ENABLE_QUICK_EDIT_MODE` (with `ENABLE_EXTENDED_FLAGS`), `ENABLE_LINE_INPUT`, `ENABLE_ECHO_INPUT`, `ENABLE_PROCESSED_INPUT`, `ENABLE_MOUSE_INPUT`, `ENABLE_WINDOW_INPUT`; leaves `ENABLE_VIRTUAL_TERMINAL_INPUT` **off** |
| `restore()` | restores both saved modes; idempotent; a no-op when raw mode was never entered; also reached from an `atexit` backstop |
| `size()` | `GetConsoleScreenBufferInfo` → `srWindow` (the visible window), 24×80 fallback; re-read every tick, never cached |
| `readEvent(ev, ms)` | `WaitForSingleObject(STD_INPUT_HANDLE, ms)` then `_kbhit()`/`_getch()`; decodes `\r`, `\b`, `\t`, `Esc`, `0`/`224`-prefixed arrows, printable ASCII, and `Ctrl+C`/`Ctrl+D`/`Ctrl+Z` → `Eof` |
| `write()` | `WriteFile` loop on `STD_OUTPUT_HANDLE` (works on a console and on a redirect) |
| `flush()` | no-op — `WriteFile` is unbuffered |
| `isTty()` | `GetConsoleMode` succeeds on both std handles |
| `nowMs()` | `GetTickCount64()` — monotonic and cheap, the single clock source |
| `Terminal::create()` | returns `std::make_unique<Win32Terminal>()`, registers the one `atexit` backstop |
| `installShutdownHandlers()` | `SetConsoleCtrlHandler(handler, TRUE)`; the handler only sets the flag |
| `shutdownRequested()` | read-and-clear, input thread only |

**A VT-enable failure is a loud startup error** (`fatalStartup` → message on stderr + `exit(EXIT_FAILURE)`),
because v3 has no ANSI-free animated fallback and no `--diag`. `enterRawMode()` is only reached when the caller
has already decided it is not in plain line mode (`isTty()` / `--no-tty` are the selectors — v2 §T2.5 Step 1),
so both "no console at all" and "console refuses VT" stop the program.

### Defect found and fixed during this verification

The first version followed the plan's snippet `if (!_kbhit()) return false;`. A live console leaves a
**`FOCUS_EVENT`** (input record type 16) in the input buffer when the window is activated; `_kbhit()` filters
that record out, so the console handle stays signaled forever and every later `WaitForSingleObject` returns
immediately — i.e. the input thread would spin at 100 % CPU, exactly plan risk 18. The fix is
`drainFilteredRecords()`: consume the records `_getch` can never deliver, one at a time, **stopping at the first
key-down record** so a keystroke racing in is never dropped. The harness now shows `16,109,110,109,109` ms for
five 100 ms waits — one drained focus event, then four full-length waits — and an idle 1000 ms wait costs
**0 ms** of process CPU.

## 3. Backend hand-check harness

Because `main`/`ConsoleApp`/`Renderer` are still other owners' `TODO` stubs, the full application cannot animate
yet, so the backend was verified directly against the frozen `Terminal` interface with a scratch harness (never
committed — the same practice W1 used for T1.1's pty checks). Techniques that make the check real rather than
declared:

- it **attaches a real console** (`CONOUT$`/`CONIN$`, or a private `AllocConsole` host for the resize take),
  so `GetConsoleMode`/`_kbhit`/`_getch` and `SetConsoleMode` run on a genuine console;
- keys are injected with **`WriteConsoleInputA`**, which the console host translates exactly like physical keys;
- VT output is proven by **reading the screen buffer back**: after writing `ESC[2J ESC[H ESC[31mVT ESC[0m`,
  `ReadConsoleOutputCharacterA` returns `"VT  "` (not `"^[[31mVT"`) and `ReadConsoleOutputAttribute` reports
  `FOREGROUND_RED` — i.e. ANSI is interpreted, not printed.

**Result: 49 passed, 0 failed** on a private conhost console; **47 passed, 0 failed** under the shell's ConPTY
console (two checks are inherently unobservable there — see §4).

| Group | Checks that passed |
| --- | --- |
| Environment | `isTty()` true on a console pair; live `size()` (120×30, the shell's real geometry) |
| Clock | `nowMs()` millisecond-scaled, monotonic over 200 reads |
| Mode contract | VT processing set; `DISABLE_NEWLINE_AUTO_RETURN` set; QuickEdit, echo, line, processed, mouse, window, VT-input all clear; `ENABLE_EXTENDED_FLAGS` set; `enterRawMode()` idempotent |
| VT output | escape sequences interpreted; `ESC[31m` sets the red attribute |
| Timed read | `false` on timeout; one focus-event drain then full-length waits; 1000 ms idle = 0 ms CPU; `timeoutMs == 0` polls |
| Key decode | `A`, `5`, `!`, space, Enter, Backspace, Tab, Esc, ↑ ↓ ← →, Ctrl+C/D/Z → `Eof`; an unmapped extended key (F1) is ignored **and the next key still decodes** (no desync) |
| Resize | `size()` follows a live window resize 30×120 → 40×100 and back |
| Restore | exact input+output mode restoration; `restore()` before raw mode is safe; `restore()` idempotent; destroying the terminal restores the console |
| Shutdown | read-and-clear semantics |

### Proven loud-failure path

There is no `--diag` any more, so the VT/no-console failure was checked by running the harness with a pipe for
stdout (no console): `enterRawMode()` prints
`csopesy: fatal: no console on standard input/output; run with --no-tty for plain line mode` and exits **1**.

## 5. Environment finding — the built `csopesy.exe` is removed by a security product

While producing the evidence above, every freshly linked `csopesy.exe` (Debug **and** Release) was **deleted
within ~5 s**, and once deleted the name stayed unusable in that directory (`Permission denied` on relink).

Evidence gathered:

- `csopesy_tests.exe` (same toolchain, same `libcsopesy_core.a`, unsigned) **survives** and runs, so this is
  **not** a defect in T3.1 or in any source file.
- A byte copy of `csopesy_tests.exe` named `csopesy.exe` survives; a fresh link of the real `csopesy.exe`
  content is deleted even when renamed to `other_name.exe` — so the trigger is the **built binary's content**,
  not its name or directory.
- Windows Defender is **disabled** on this machine (`Get-MpPreference` fails with `0x800106ba`) and its
  operational log has no detection events; **Norton** services (`NortonSvc`, `NortonUI`) are running.

**Action for W3 before T3.4/T3.3 and before freezing:** add an exclusion for this repository (at minimum
`frozen\` and `build\`) in Norton, then confirm `frozen\csopesy.exe` is still present a minute after it is
copied. If it disappears during the quiz, the graded run configuration has no binary to launch. This is a
machine configuration issue; nothing in the repository should be changed for it.
